# AI Usage Policy

AI-assisted contributions are welcome. A human checks every change and answers for it.

- **Disclose exactly what generated it.** In the pull request or issue, name the
  model and the tool, and how much of the work it did:

  ```
  Generated by Opus 5.5 via Claude Code: the fix and most of the tests.
  I reviewed and edited all of it.
  ```

  A tool without a model ("Used Codex CLI") is not enough. No AI used: write
  nothing.

- **Understand it.** Explain your change, and how it touches the rest of the
  proxy, in your own words, without the AI.

- **Check it before you send it.** Run `npm test`, try it against a real client
  if it touches requests or streaming, and read the diff. You answer for the
  code, not the AI.

- **Issues: AI may draft, a human edits.** Keep what happened, what you
  expected, and the real log output, not an AI summary of it.

Pull requests their author clearly did not read or test may be closed without a
detailed review; open a new one once you have checked it. Maintainers follow
the same rule.

## Why

Generating a pull request takes minutes; reviewing it takes hours. When the
author cannot explain the code, the maintainer ends up talking to a model
through a middleman and writing the fix anyway. It matters most in the fragile
parts: session reuse, account failover, streaming, and DeepSeek's undocumented
wire format, where a blind patch fixes one case and breaks another.

This is not anti-AI: FreeDeepseekAPI is built with plenty of it. The problem is
unchecked output, not the tool.
